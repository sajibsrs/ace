## Stdlib: `sys` and `time`

Stdlib #10–11; the chapter's shared rules are in `spec/std/README.md`.

10. `sys` file I/O and process-start access (implemented) — file I/O is pure Ace over `extern "c"` system-library declarations (Darwin libSystem, Linux glibc), exactly the `fmt` pattern, in one OS file per target: `std/sys/os/darwin-arm64.ace` and `std/sys/os/linux-x64.ace`. Process arguments and environment entries use compiler-backed declarations because Ace intentionally has no pointer arithmetic over the platform's C pointer arrays. The public surface:
    - `Fd: distinct i32` — the descriptor handle. Canonical zero is fd 0 (stdin, valid), so zero is not an invalid sentinel; `-1` marks a failed `open`, compared directly (`fd == -1`); no named invalid constant.

    - Standard descriptors (implemented): `pub stdin`, `pub stdout`, and `pub stderr` are `const Fd` globals holding fds 0, 1, and 2, valid from process start and consumed through the ordinary `read`/`write` operations. Spellings mirror the OS words (`stdin`/`stdout`/`stderr`), consistent with the flag-constant rule; the owner's original `in` spelling is unavailable because `in` is a keyword. They are the only named descriptor constants. Their initializers are distinct-type constructor constants, folded by the emitter under the widened constructor-constant rule recorded in the implementation-phase list.
    - `read(fd: Fd, buf: mut []u8): int, Error` — bytes read; `0` with `null` error is EOF. Buffer content writability is carried in the parameter's type (Mutability #10); replacing the caller's buffer variable would take a separate `mut buf` mark.
    - `write(fd: Fd, data: []u8): int, Error` — bytes written; partial counts are legitimate results and are returned as-is with no hidden retry (all-or-retry policy belongs to callers or a later honestly-named `write_all`).
    - `close(fd: Fd): Error`.
    - `open(path: string, flags: i32): Fd, Error` and `open(path: string, flags: i32, mode: u32): Fd, Error` — the 2-arg form passes `mode: 0` to the same fixed 3-parameter extern (POSIX ignores mode without `O_CREAT`).
    - Error mapping: each operation has its own nominal error domain (`OpenErr`, `ReadErr`, `WriteErr`, `CloseErr`). A wrapper captures errno immediately after failure and returns it as `error.code`; `pub errno(): i32` remains available for direct platform work but is not needed to preserve a wrapper failure.
    - Paths: copied into a fixed stack buffer of the target's `PATH_MAX` including NUL (1024 bytes on Darwin, 4096 on Linux — the kernel rejects longer paths itself, so the buffer never rejects a legitimate one), NUL appended, then passed to the OS. An overlong path returns the ordinary `open` error with `ENAMETOOLONG`, and a path holding a NUL byte, which C would read as its end, with `EINVAL`, each written into errno by `sys` itself. Every public `sys` function is allocation-free; only callers allocate.
    - Flags and creation permissions: raw `pub` i32 flag constants mirror the target's values and spellings exactly (`O_RDONLY` … `O_NONBLOCK`, including POSIX `O_CREAT`) and compose with `|`. The POSIX permission constants are the `u32` set `S_IRWXU`, `S_IRUSR`, `S_IWUSR`, `S_IXUSR`, `S_IRWXG`, `S_IRGRP`, `S_IWGRP`, `S_IXGRP`, `S_IRWXO`, `S_IROTH`, `S_IWOTH`, and `S_IXOTH`, likewise composed with `|` for the mode argument of file and directory creation. They request permissions; the process umask may remove bits. File-type and special-mode bits remain deferred until real usage justifies them. Rule: `sys` mirrors OS spellings for OS-defined words; Ace names belong to Ace abstractions. Errno name constants remain deferred.
    - Implementation facts: the raw bindings are private link-named externs (on Darwin `c_open` → `__open` because `open` is variadic and Apple arm64 passes variadic args on the caller's stack; linux-x64 binds the variadic `open`, whose mode travels in a register). Error domains keep one variant set with each target's errno numbers, except that `ForkErr.process_limit` (Darwin `EPROCLIM`) exists only on Darwin. `write(fd: Fd, data: []u8)` accepts text as well because `string` and `[]u8` share identity; a spelling-only overload would be a duplicate declaration.
    - Secure entropy (implemented): `random(storage: mut []u8): Error` fills
      caller-owned storage from the operating system and allocates nothing.
      Empty storage succeeds without a foreign call. Both targets use `getentropy`
      in chunks of at most 256 bytes, retries `EINTR`, and returns every other
      failure through `RandomErr(code)` after capturing errno immediately.
    - Descriptor control (implemented): `ioctl(fd: Fd, request: uint): Error` performs a request with no unnamed argument; `ioctl(fd: Fd, request: uint, data: mut []u8): Error` passes the address of the caller's first mutable byte as the single unnamed argument and requires nonempty storage. Failure is `IoctlErr` with errno captured immediately; an empty data view fails locally with `EINVAL`. The request type is `uint` because Darwin declares it as `unsigned long`, which is 64 bits on Apple arm64; it is not narrowed to the 32 bits occupied by current encoded values. The target layer binds the genuinely variadic `ioctl` entry point so Apple arm64 places the unnamed pointer in its required eight-byte stack slot. The Darwin BPF requests `BIOCGBLEN`, `BIOCPROMISC`, `BIOCSETIF`, and `BIOCIMMEDIATE`, plus the classification errno constants `EBUSY` and `EACCES`, are exposed only for the packet-sniffer proof and retain their target spellings and values; the BPF requests exist only on darwin-arm64. Their raw definitions, the verified `ifreq` and `bpf_hdr` layouts used to derive them, and the C binding stay in `std/sys/os/darwin-arm64.ace`. BPF records use the native 18-byte `bh_hdrlen` through its last declared field, excluding the C structure's two tail-padding bytes, and advance by four-byte `BPF_WORDALIGN`. The byte-buffer overload does not infer an object type, validate an encoded request size, reinterpret storage, or promise that a request is portable; the caller selects a target request and supplies its exact native bytes.
    - Filesystem metadata and mutation (implemented): `FileType: enum { unknown, regular, directory, symlink, other }` classifies only the stable categories exposed by the facade. `FileInfo: struct { size: u64, file_type: FileType }` is canonical zero for a failed query. `stat(path: string): (FileInfo, Error)` follows symbolic links and returns their targets' metadata; `lstat(path: string): (FileInfo, Error)` describes a final symlink itself. Both expose byte size and file type only. Timestamps, permissions, ownership, inode/device identity, link count, and allocated blocks remain additive. `canonical(path: string, buf: mut []u8): (usize, Error)` writes the absolute path of an existing file, every symlink and `.`/`..` resolved, into `buf` without a NUL and returns its byte count; `executable(buf: mut []u8): (usize, Error)` does the same for the running executable. The kernel resolves both (darwin `getattrlist(ATTR_CMN_FULLPATH)`; linux `readlink` of `/proc/self/fd/N` over an `O_PATH` descriptor, or of `/proc/self/exe`), so neither needs read permission and no libc path algorithm runs. Storage too small for the result fails with `capacity`, writing nothing usable. `mkdir(path: string): Error` is the portable form: on POSIX it requests `S_IRWXU | S_IRWXG | S_IRWXO` (`0777`) and lets the process umask select effective permissions. It creates exactly one directory and never creates missing parents. The overload `mkdir(path: string, mode: u32): Error` supplies an explicit POSIX permission request, matching the existing creation-mode parameter of `open`; it is a target-specific facility, not a cross-platform permission abstraction. Windows permissions are ACL-based, so a future Windows target retains the one-argument operation and must separately carve richer security rather than pretending POSIX owner/group/other bits represent ACLs. `rename(old_path: string, new_path: string): Error` and `unlink(path: string): Error` perform exactly the corresponding OS operation, with no recursive behavior or retry.
    - Directory iteration (implemented): `Dir: struct { fd: Fd, buffer: [4096]u8, next: usize, count: usize, base: i64, active: bool, done: bool }` (Linux has no `base`: `getdents64` keeps the offset in the descriptor) is caller-owned buffered iteration state, not an alias of `Fd` and not an ownership-tracked value. Its representation is visible under the ordinary struct rules but its fields collectively form handle state; callers do not edit them between directory operations. Its canonical all-bits-zero value is invalid even when descriptor zero is usable. `opendir(path: string): (Dir, Error)` opens only a directory. `readdir(mut dir: Dir, name: mut []u8): (usize, FileType, bool, Error)` returns, in order, the name byte count, file type, end flag, and error. The parameter mark on `mut dir: Dir` grants updates to the caller's iteration value and must be repeated at the call; independently, type-position `mut` on `name` grants writes to its bytes without replacing its descriptor. A successful entry returns `(name_length, file_type, false, null)`. End returns `(0, unknown, true, null)`. Failure returns `(0, unknown, false, error)`. Names are exact bytes with no appended NUL; `.` and `..` are skipped. Enumeration order is the OS order. An entry file type may be `unknown`, in which case callers use `stat` when classification is required. If the name buffer is too small, the operation returns `ReaddirErr(ERANGE)` without truncating or consuming that entry, so a later call with a larger buffer retries it. `closedir(mut dir: Dir): Error` closes the resource and replaces the caller's complete `Dir` value with canonical zero, including on close failure. Copying `Dir` copies its descriptor and buffered cursor; aliases are not found or invalidated and using them after either copy is closed has the ordinary manual-handle hazards. There is no hidden allocation, ownership, destructor, automatic close, sorting, recursion, path joining, or retained entry view.
    - Each added operation returns the ordinary packed `Error` type, null on success; error-domain declarations are constructors/classifiers, not signature result types. The public domains are exactly `StatErr`, `CanonicalErr`, `ExecutableErr`, `MkdirErr`, `RenameErr`, `UnlinkErr`, `OpendirErr`, `ReaddirErr`, and `ClosedirErr`, and each wrapper captures errno immediately. Every path uses the same fixed `PATH_MAX` stack conversion as `open`; overlong paths report that operation's own domain with `ENAMETOOLONG`. Target structure layouts, directory-record parsing, `O_DIRECTORY`, and raw link names remain private to the target layer.
    - Process arguments: `argc(): usize` returns the process argument count in constant time. `arg(index: usize): string` requires `index < argc()`, scans only that NUL-terminated entry, and returns a zero-copy read-only view valid for the process lifetime. Index zero is the program invocation name. The bounds precondition follows the ordinary sequence contract: debug builds diagnose a violation and release assumes it.
    - Environment: `envc(): usize` scans the null-terminated environment pointer array on every call and is therefore O(environment entries); callers capture the count before iteration. `env(index: usize): string` requires `index < envc()`, scans only the selected NUL-terminated entry, and returns its raw zero-copy `KEY=VALUE` bytes. Behavior after environment mutation through linked C code is not yet specified. All four operations allocate nothing. Darwin reads the libSystem `_NSGetArgc`/`_NSGetArgv`/`_NSGetEnviron` accessors. On linux-x64 an Ace `main` stores its entry argc and argv in two private object words, so an Ace object linked under a C `main` sees `argc()` as zero; the environment is glibc's `environ`, read at each call.
    - Process termination: `exit(code: int)` terminates the process immediately with the requested status and never returns. It is callable from any function and declares no return value. It does not unwind the call stack, run function-scope defers, or invoke C-runtime exit handlers. The `int` is passed through the target's process-exit boundary; which status bits a parent observes follows the target operating system. This is deliberate termination with a caller-chosen status, distinct from `panic`, which reports a broken invariant best-effort and aborts with `SIGABRT` (Errors #15). The OS-neutral `sys` facade calls its private target OS layer; each target OS file converts the code to `i32` and calls the system library's `_exit(2)`. No bottom type, general non-returning-function annotation, or compiler intrinsic is introduced.
    - Process creation and waiting (implemented): `Process: distinct i32` is a process handle. `fork(): (Process, Error)` performs exactly one process duplication; it returns the child process handle in the parent, `Process(0)` in the child, or `Process(-1)` with `ForkErr` on failure. It returns in both processes exactly as the OS operation does and performs no allocation, retry, callback, or descriptor cleanup. `ProcessStatus: struct { exited: bool, code: int, signal: int }` is the portable completed-child result. `wait(process: Process): (ProcessStatus, Error)` requires a positive child handle and blocks for that exact child without retrying interruption; zero and negative handles fail with `WaitErr(EINVAL)` rather than acquiring POSIX process-group or any-child meanings. Normal termination returns `exited: true`, the unsigned 8-bit exit code widened to `int`, and signal zero. Signal termination returns `exited: false`, code zero, and the positive signal number. Failure returns canonical-zero status with `WaitErr`. Stopped/continued observations and nonblocking/any-child waits are additive. The facade never exposes Darwin's encoded wait-status word.
    - Caller-buffer `fill_args`/`fill_env`, keyed environment lookup, and `setenv`/`unsetenv` interaction are additive follow-ups.
11. `time` monotonic clocks (implemented) — two parameterless operations return system-wide monotonic clock readings in nanoseconds from origins reset at every boot. `pub elapsed(): u64` continues advancing during system sleep, so differences between its readings measure real elapsed time across sleep and wake cycles. `pub awake(): u64` pauses during system sleep and resumes when the system wakes; it advances whenever the system is awake, regardless of whether this or any other process is running, scheduled, or blocked — it is never process CPU time. Both clocks are immune to calendar-clock changes. Each returned value is a clock reading, not a duration by itself; readings are only meaningfully subtracted when both came from the same operation. Each operation is allocation-free and has no `Error` return: the platform clock reads do not fail here, so an error channel would buy nothing. Implementation is `std/time/mod.ace` over one private OS file per target. `std/time/os/darwin-arm64.ace` calls Darwin `clock_gettime_nsec_np` (`CLOCK_MONOTONIC_RAW` for `elapsed`, `CLOCK_UPTIME_RAW` for `awake`). `std/time/os/linux-x64.ace` converts a `clock_gettime` timespec to nanoseconds (`CLOCK_BOOTTIME` for `elapsed`, which NTP may slew but never steps; `CLOCK_MONOTONIC_RAW` for `awake`). The clock-id constants stay private. Calendar time, process CPU time, duration conversion/formatting, and a process-sleep function are deliberately outside this surface; each belongs to its own decision.
24. `exec` spawning (implemented) — `exec` starts programs as child processes over `sys`, importing `sys` and `mem`, so `sys` stays import-free (#21, #22). `spawn(argv: []string): (sys.Process, Error)` starts `argv[0]`, searched in `PATH`, with `argv` and this process's environment through `posix_spawnp`, no shell between; the returned handle is waited with `sys.wait`. It copies the strings into NUL-terminated `mem` storage released before return. An empty `argv` or an argument holding a NUL byte fails with `SpawnErr(EINVAL)`; a platform failure returns `sys.Process(-1)` with `SpawnErr` carrying the code `posix_spawnp` returns. File actions, attributes, and an explicit environment are additive.
