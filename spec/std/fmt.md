## Stdlib: formatted output

Stdlib #12; the chapter's shared rules are in `spec/std/README.md`.

12. Formatted output (implemented) — `fmt.printf("name=%s count=%d ratio=%.2f\n", name, count, ratio): int` is one compiler-recognized public `fmt` name for compile-time-static formats and runtime values. The format must be a string literal or a const-global `string` initialized from a static string literal; runtime-created or runtime-selected formats are deferred. The compiler parses the format and checks argument count and exact types. There is no runtime format parser, type tag, argument pack, `any`, reflection, allocation, hidden C variadic call, or dependency on C formatting; generated work is direct typed formatting plus the OS output boundary.
    - Initial conversions are `%d` signed decimal, `%u` unsigned decimal, `%b` unsigned binary, `%o` unsigned octal, `%x`/`%X` lower-/uppercase unsigned hexadecimal, `%f` fixed decimal, `%s` exact string bytes, `%c` one byte, and `%%` one literal percent consuming no argument. Binary, octal, and hexadecimal emit digits only, with no base prefix; zero emits `0`. Pointers, scientific/general float conversions, booleans, errors, and custom formatting remain additive.
    - Exact types: `%d` accepts `int`; `%u`, `%b`, `%o`, `%x`, and `%X` accept `uint` or `usize`; `%f` accepts `f32` or `f64`; `%s` accepts `string`, including embedded NUL bytes; `%c` accepts `u8` and writes exactly that byte. Transparent aliases share their target; distinct types require explicit conversion. Other narrow integers remain explicit. Conversion context materializes literals as `int` for `%d`, `uint` for `%u`/`%b`/`%o`/`%x`/`%X`, `f64` for `%f`, and `u8` for `%c`; a literal intended as `usize` is written `usize(...)`. An argument with no value, such as a `panic(...)` call, is a compile-time error. `%c` is deliberately byte-oriented; wider Unicode handling is additive through a future facility, while existing UTF-8 bytes may be written with `%s`.
    - `%f` defaults to exactly six fractional digits; `%.Nf` writes exactly `N`, and `%.0f` writes no decimal point. Rounding is nearest with exact ties to an even final digit, applied to the exact `f32` or `f64` input and independent of the caller's ambient floating-point rounding mode; the helper restores that mode before returning. The original sign is retained when a negative value rounds to zero, including negative zero. Non-finite spellings are always `nan`, `inf`, and `-inf`; precision does not alter them and a NaN sign is not shown. `%f` never switches to scientific notation.
    - No field width, padding, alignment, explicit-plus/space sign, alternate form, dynamic `*`, or positional argument exists initially. The only modifier is the literal precision `%.Nf`; unsupported combinations are compile-time errors.
    - Output is buffered per call: pieces accumulate left to right in fixed storage in the caller's frame, written to standard output when the storage fills and when the call ends, so a call whose output fits makes one write. Nothing is buffered across calls; when `printf` returns, its bytes have been written. A positive partial write is accumulated and its remaining segment retried; text larger than the storage is written directly from its source. Complete success returns the total emitted byte count, including every literal and formatting byte; empty output returns zero. A zero or negative OS result stops output immediately, suppresses the rest of the call, and is returned unchanged even after earlier successful bytes, matching `print` and `println`.
    - `fmt.printf(fd, format, ...)`, with a first argument of type `sys.Fd`, is the same call writing to that descriptor instead of standard output, as C's `dprintf`: identical checks, buffering, result, and failure rules, with value arguments counted after the format.
    - Only the canonical standard-module member receives special handling, including through selective import; user declarations named `printf` are ordinary. `fmt.printf` is direct-call-only and cannot be used as a function value because its checked parameter shape depends on the format. Every runtime argument is evaluated exactly once in source order and captured before output begins, so output failure never suppresses later argument evaluation or side effects. The compiler then emits direct typed calls: it opens a sink over the storage, writes each piece through an exact-type specialization of a shared piece writer, and closes the sink. The sink (as in Zig's `std.Io.Writer`) appends to its storage and, when a piece does not fit, hands the buffered bytes to its drain; a failure sticks and later writes are no-ops. Width padding and zero runs stream as fills (as musl's `pad` and BSD `vfprintf`'s `PAD` do), never stored whole. No runtime dispatch or metadata exists.
    - A conversion may carry a width, `%[0][width][.precision]conv`: a decimal width of 1 through 1000000 is a minimum byte count, padding with spaces before the text; the `0` flag (numeric conversions only) pads with zeroes after any `-` instead, except that `nan` and `inf` still take spaces. A longer value is never truncated. Left alignment, sign flags, base prefixes (spell them as literal text: `0x%08x`), and dynamic `*` width remain additive.
    - Precision is limited to `0...324` inclusive. Float helpers use one fixed 640-byte stack buffer, sufficient for a sign, 309 integer digits, a decimal point, and 324 fractional digits; conversions reuse it rather than reserving storage per argument. This bound can expose the smallest nonzero `f64` magnitude in fixed notation while keeping runtime and declared memory bounded. Static literal spans are copied from constant storage. There is no `printf`-specific format-length or argument-count cap beyond ordinary compiler limits.
    - Diagnostics distinguish a non-static format, incomplete `%`, unsupported conversion or modifier, a zero flag without a width or on `%s`/`%c`, width above 64, malformed precision, precision on a non-`%f` conversion, precision above 324, missing/extra arguments, and exact-type mismatch. They identify the conversion's decoded byte offset and relevant argument; after a malformed format, derived count/type errors for that call are suppressed.
    - Implementation must cover exact runtime bytes and counts for every conversion and boundary; changing runtime values; integer extrema; binary, octal, both hex cases, and both unsigned types; float defaults, explicit precisions, ties-to-even, signed rounded zero, non-finites, and precision 324; empty/NUL-containing strings; byte extremes; `%%`; mixed calls; evaluation order/once-only capture; and closed-output failure. Success fixtures cover literal/const-global formats, qualified/selective imports, aliases, and explicit conversions; diagnostics cover every rejected format, count, type, distinct/narrow type, dynamic format, and precision 325. Normal and sanitizer suites must pass, and object inspection must show no C `printf`, variadic call, allocator, runtime parser, or formatting metadata. When implementation lands, the standard-library guide and its compiler-checked documentation fixture must be updated in the same change; planned features remain outside the implemented manual.
