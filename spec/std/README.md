## Stdlib
Decision: minimal, allocation-explicit, one fixed process-wide strategy.

Naming convention: public standard-library names are short and descriptive.
Language, `std`, and first-party `pkg` names are one word wherever one word is
unambiguous (`match`, not `is_match`): the explicit signature already states
the rest, and these names are the ones every programmer memorizes. Other code
names for expressiveness instead. Functions use lowercase words separated by
underscores when more than one word is needed; types, error domains, and other
type-like names use compact PascalCase.
The module qualifier supplies domain context, so a member does not repeat the
module or its primary subject when the shorter name remains unambiguous. Keep
the subject when a module can expose multiple categories of the same form;
`net.SocketType` and `sys.FileType` therefore remain specific rather than
collapsing to `Type`. Preserve each identifying word;
shorten only established, immediately recognizable terms such as `Err`, `Addr`,
and `Fd`, never an ordinary word merely to remove characters. In particular,
`ProcessStatus` remains complete because `Stat` already names filesystem status
and statistics. Error domains use the operation name plus `Err`, omitting a
generic mutator verb when the operation itself is named as a reversible property
(`reuseaddr` / `ReuseaddrErr`, `nonblock` / `NonblockErr`). Public facades and
their selected OS files expose identical spellings. OS-defined constants and
established boundary terms retain their standard spellings (`O_NONBLOCK`,
`mkdir`, `opendir`, `popcount`, `clz`, `argc`, `errno`).

1. Error inspection uses the predeclared packed `Error` value's direct read-only `code`, `domain`, `name`, and `message` fields (see: Errors). The description fields use only compiler-emitted static data when referenced. The `fmt` surface adds no `Error` overload.
2. The raw memory layer is exported by `mem`: the three allocation functions from Memory #10 (`alloc`, `realloc`, and `release`) with their explicitly instantiated typed overloads from Memory #22–27, and the allocation-free byte operations from Memory #15–16 (`copy`, `move`, `fill`, `zero`, and `compare`). `equal` accepts byte-backed arrays and the shared `string`/`[]char`/`[]u8` view type, including writable forms and independently sized fixed arrays, and returns `bool` after comparing length then exact bytes; it allocates, converts, decodes, and normalizes nothing.
3. v1 uses the platform general-purpose allocation boundary directly and adds no release-mode Ace metadata. `[]u8` already carries the only language-visible allocation facts needed by the raw API: pointer and requested byte length. Alignment is supplied explicitly to `mem.alloc`; unsupported alignment is an invalid request and returns null rather than being silently weakened.
4. Debug-build allocation tracking is tooling, not another allocator strategy or a release-mode representation change.
5. Import resolution: bare source name = stdlib only (`import math`, `import min from math`); local files always use an exact `.ace` path (`import util: "./util.ace"`, `import value from "./util.ace"`). A local file cannot shadow a standard module. A bare qualified, aliased, or selective std import resolves either `std/<name>.ace` for a single-file module or `std/<name>/mod.ace` for a directory module. Defining both is an ambiguous std module and a compile error; defining neither reports both attempted paths. Files inside a directory module import one another by relative `.ace` paths, but canonical-path enforcement rejects an import of any implementation file from outside that directory module; `mod.ace` is the only external target. Directory packages for user code remain future work. A single file's canonical path remains its compilation identity, while the `mod.ace` boundary determines external visibility. `std/@/` is the compiler-reserved standard-library implementation namespace and uses an unquoted, suffixless internal source such as `import big: @bigint` or `import value from @shared`; `@name` resolves only to the exact file `std/@/name.ace` beside the compiler. It is not a general path prefix, attribute, package namespace, or user-definable mechanism, and adding `.ace` is invalid syntax. Every source canonically beneath the compiler-shipped `std/` tree may import these files, including imports between reserved files, while sources outside that canonical tree may not. The restriction is checked after path canonicalization, so relative traversal, alternate lexical paths, and symlinks cannot expose reserved modules. It applies to import edges, not roots, and does not attach special status to equivalent source copied elsewhere. No bare `@` or `internal` module exists.
6. Platform access uses the target OS's stable public interface. A supported
   direct syscall may be used where the target guarantees it; otherwise the
   target layer uses the OS-provided system library or framework through its
   declared ABI (`extern "c"` for macOS libSystem). The ABI spelling describes
   how to call the platform, not a dependency on the C language or runtime. This
   is the OS front door, not permission to outsource Ace behavior; C Interop #4
   defines the boundary.
7. `string` is the complete-text intent spelling of `[]char`/`[]u8` (UTF-8 by convention); all three share type identity and machinery.
8. v1 contents — eight modules: `mem` (the raw allocation layer plus explicit byte/memory operations), `sys` (OS calls), `fmt` (print/format), `bits` (explicit access to and operations on machine representations), `math` (`sqrt`, `floor`, `ceil`, `fma`, `exp`, `log`, `pow`, `sin`, `cos`, classification, `abs[T]`, `min[T]`/`max[T]`, …), `ascii` (ASCII byte classification, conversion, and comparison), `str` (byte/string operations), `simd` (`f32x4`, `i8x16`, arithmetic and shuffles emitting NEON directly — explicit vectorization, zero compiler analysis, for what auto-vectorization (Compiler #6) does not cover). Copying a float's complete representation to an integer or back is the `bitcast` builtin (Memory, untyped storage), which preserves signed zero, infinities, subnormals, and NaN payloads; ordinary numeric casts retain their numeric meaning.
   Integer representation operations are exact overloads for `u8`, `u16`, `u32`, and `u64`. `bits.popcount(value): uint` returns the number of set bits. `bits.clz(value): uint` and `bits.ctz(value): uint` return the number of consecutive leading and trailing zero bits, respectively; for zero they return the operand width. `bits.bswap(value)` returns the same type with its bytes reversed and is the identity for `u8`. `bits.rotl(value, count: uint)` and `bits.rotr(value, count: uint)` return the same type and reduce `count` modulo the operand width, so every count is valid. `bits.wradd(a, b)`, `bits.wrsub(a, b)`, and `bits.wrmul(a, b)` take two operands of one of those types and return the same type, computing the result modulo 2^width in every build mode; unlike `+`, `-`, and `*` they never report overflow (Safety & Debug Builds #6), which hashing, checksums, and pseudorandom generators require. Signed integers and `usize` require an explicit conversion to a fixed-width unsigned type; transparent platform aliases share their underlying overload as usual (`uint` is `u64` on Apple arm64). The three counts return `uint`, rather than `int` or an artificially narrow integer, because their result domain is intrinsically nonnegative; that accuracy costs no runtime performance. All operations allocate nothing and lower to target instructions without runtime-library calls.
   Float classification is the exact `f32`/`f64` overload set `math.isnan(value): bool`, `math.isinf(value): bool`, and `math.isfinite(value): bool`. `isnan` recognizes every exponent-all-ones, nonzero-fraction encoding, including quiet and signaling NaNs with either sign. `isinf` recognizes only positive and negative infinity. `isfinite` recognizes zeros, subnormals, and normal finite values. The pure-Ace implementations inspect representations through `bits`, allocate nothing, and make no libm call.
   Exact rounding operations are the `f32`/`f64` overload set `math.sqrt(value)`, `math.floor(value)`, and `math.ceil(value)`, each returning its operand's type. They are exactly the IEEE-754 operations under round-to-nearest-even: `sqrt` is correctly rounded at the operand's own width (an `f32` root is rounded once at `f32` precision), `floor` and `ceil` round to the integral value toward negative or positive infinity. Zeros, infinities, and already-integral values return unchanged (`sqrt(-0.0)` is `-0.0`, `ceil(-0.25)` is `-0.0`), a NaN operand returns a NaN, and `sqrt` of a negative nonzero value returns a NaN whose sign and payload are unspecified. No errno or floating-point flag is observable. They allocate nothing, make no libm call, and lower to `fsqrt`, `frintm`, and `frintp` (x64: `sqrts`, `rounds`). Results are floats; a float-to-integer conversion remains an explicit cast. `math.fma(a, b, c)` joins them: the `f32`/`f64` overload set computing `a * b + c` with a single rounding of the exact product and sum — IEEE-754's fusedMultiplyAdd, lowering to `fmadd` (x64: `vfmadd`), so `fma(inf, 0, c)` is a NaN. An ordinary `a * b + c` is never contracted into it: a fused result is asked for explicitly, and both spellings keep the value their own text states.
   Exponential, logarithm, power, sine, and cosine are the `f32`/`f64` overload set `math.exp(value)`, `math.log(value)`, `math.pow(base, exponent)`, `math.sin(value)`, and `math.cos(value)`, each returning its operands' type. They are pure Ace with no `extern` and no platform-libm call (C Interop #4), so results are identical on every target. Every `f64` result is within 1 ULP of the exact result over the whole finite domain, and so is every `f32` result. Special cases follow C99 Annex F: `exp(±0)` is `1`, `exp(+inf)` is `+inf`, `exp(-inf)` is `0`, overflow gives `+inf`, and underflow is gradual through subnormals; `log(+0)` and `log(-0)` are `-inf`, `log` of a negative value is a NaN, `log(1)` is `+0`, and `log(+inf)` is `+inf`; `sin(±0)` is `±0`, `cos(±0)` is `1`, and `sin` or `cos` of an infinity is a NaN; `pow(x, ±0)` is `1` and `pow(1, y)` is `1` for every operand including a NaN, `pow(-1, ±inf)` is `1`, a finite negative base with a finite non-integer exponent is a NaN, `pow(±0, y)` and `pow(±inf, y)` split on whether `y` is an odd integer, and `pow(x, ±inf)` splits on whether `|x|` is below or above 1; `pow(x, 2)`, `pow(x, 1)`, `pow(x, -1)`, and `pow(x, 0.5)` for a positive base are correctly rounded; `pow` is exact whenever the result is a representable integer power, is table-driven with its two 128-entry tables derived in `std/@/math_tables.ace`, and its `f64` result is within 0.51 ULP, or within 1 ULP when the result is subnormal, while its `f32` result, from a separate plain-`f64` kernel over the same tables, is within 0.51 ULP; a NaN operand returns a NaN, and a generated NaN has unspecified sign and payload. No errno or floating-point flag is observable, and the default rounding mode is assumed. `sin` and `cos` cover the full finite domain: arguments beyond about 1.6e6 use exact Payne–Hanek reduction against a 1280-bit table of 2/π rather than an unspecified range. Platform libm may serve as a differential-test reference, never as a dependency.
   Intrinsic declarations: a function declaration may use the trailing body substitute `intrinsic`, as in `pub popcount(value: u32): uint intrinsic`, only for an exact compiler-provided standard-library operation. It is not a user-extensible foreign or assembly hook. The admitted public operations are the nongeneric, top-level `bits` overloads and the `math` exact-rounding overloads specified in #8; methods, private declarations, generics, specializations, `extern`, and `export` uses are rejected. The compiler emits an ordinary callable symbol for every admitted declaration so explicitly typed function values and indirect calls have the same semantics as direct calls. A statically resolved direct call may lower inline to the same instruction sequence.
   The compiler-shipped `std/@/byte_load.ace` module additionally admits exactly `pub unaligned_u64(text: string, index: usize): u64 intrinsic`. Only standard-library sources can import the reserved module. The caller must establish `index + 8 <= text.len` before the call; it reads one target-native-endian word without an alignment requirement and introduces no public operation, allocation, or platform-library dependency. This narrow primitive supports word-at-a-time internal byte algorithms without exposing pointer reinterpretation or a general intrinsic facility.
9. Output API begins as an exact overload set. `fmt.print(text: string): int` writes the supplied bytes exactly; `fmt.print(value: int): int`, `fmt.print(value: uint): int`, and `fmt.print(value: usize): int` write signed platform integers, unsigned platform integers, and memory-sized unsigned values in base-10 ASCII. None adds a newline or allocates; numeric conversion uses a fixed 20-byte stack buffer and covers each type's complete range. Every overload retries partial writes and returns bytes written, or the non-positive result from the current OS boundary. Overload policy (decided): the platform-word pair (`int`, `uint`) beside `usize` and `string` is the integer output set; integer widths narrower than the platform word get no overload — callers convert explicitly (`fmt.print(int(my_i32))`, `fmt.print(uint(my_u16))`) so the printed type stays visible (owner: keep narrower integers explicit for now). Float output (decided): `fmt.print(value: f32): int` and `fmt.print(value: f64): int` write shortest round-trip decimal — the fewest significant digits that parse back to the exact original value — with non-finite values spelled `nan`, `inf`, and `-inf`, negative zero keeping its sign (`-0`), and no trailing `.0`. Decimal notation for scientific exponents -6 through 20; larger or smaller magnitudes use scientific spelling (`1e21`, `1.5e-7`) with no `+` and no exponent padding. Line output (decided, implemented): `fmt.println` mirrors the complete `print` overload set (`string`, `int`, `uint`, `usize`, `f32`, `f64`) and writes exactly the corresponding `print` representation followed by one `\n`, allocating nothing. It returns the total bytes written including the newline; a non-positive result from a nonempty value write returns immediately with no newline attempted; the empty-string overload writes the newline directly; a newline failure after a written value returns the newline's failure unchanged. There is no zero-argument form — `fmt.print("\n")` already writes a bare newline. Formatted `fmt.printf` is carved in #12; a possible `Error` convenience overload remains additive.
21. Library layering — applies to `std/` and `pkg/`. (1) A library's core exposes every capability with full control: caller-owned storage or explicit `::new`/`.wipe` allocation, policy as explicit parameters, one step per operation. (2) A convenience layer composes only public core operations, with no private shortcut, so a caller can rebuild anything it does; its defaults are overridden by using the core directly. A convenience type takes its package's name and lives in `inc/<package>.ace` (`regex.Regex`, `json.Json`); a convenience of plain functions (`http.get`) needs none. (3) Either layer may allocate, always visibly: owned memory returned for `mem.release`, or state released by `.wipe()`. A module that promises to be allocation-free states it and a test enforces it, and an allocating convenience over such a module lives in a module of its own (`sys` and `file`).
