## Stdlib: `net`, `poll`, and `tcp`

Stdlib #13–15; the chapter's shared rules are in `spec/std/README.md`.

13. Networking (carving) — networking is the multi-file standard-library module rooted at `std/net/mod.ace`. Its public surface is a small stable Ace API backed by private platform bindings, not a public copy of a platform socket ABI. The core socket wrapper remains thin, allocation-free, and one-to-one with kernel operations: each public primitive performs one named state transition and adds no bundled setup, buffering, retry policy, callbacks, ownership, or hidden state. Higher-level convenience may compose these primitives later in a separately carved API. Target structure layouts, constants, byte-order details, and C link names stay private to the implementation. The initial surface is IPv4-only; IPv6 is an additive future improvement and is not prematurely folded into the first address model. `Addr4: struct { ip: [4]u8, port: u16 }` is the public endpoint value: IP octets are in ordinary textual order and the port is an ordinary host-order number. `net` privately converts that value to and from the target socket representation. Its canonical zero is `0.0.0.0:0`, suitable as wildcard address plus OS-selected port for binding. String parsing/formatting and platform-specific escape hatches are separate additive facilities; the core address and socket operations do not allocate. `net.Socket` is a public transparent alias of `sys.Fd`, not a new distinct handle or duplicated descriptor implementation. Existing `sys` operations are reused wherever their semantics are already correct for sockets, including `sys.close`; socket-specific operations stay in `net`. `SocketType: enum { tcp }` is the initial public type set, and `socket(socket_type: SocketType): (Socket, Error)` creates an IPv4 socket of that type; enum members use ordinary lowercase value naming. UDP is additive as a later `SocketType` member, and a future family-aware overload may add IPv6 without changing existing IPv4 calls. `reuseaddr(socket: Socket, enabled: bool): Error` and `reuseport(socket: Socket, enabled: bool): Error` each change exactly that socket option; `bind(socket: Socket, address: Addr4): Error` performs only the bind and never enables options implicitly. Blocking acceptance returns `(Socket, Addr4, Error)`, and blocking connection of an existing socket returns only `Error`. `Error` is last and null on success. Failed creation or acceptance returns `Socket(-1)`; failed acceptance also returns the address type's canonical zero. Each operation has its own static error domain, while the OS error number remains available through `sys.errno()`; closing retains `sys`'s existing error domain. The public domain names are exactly `SocketErr`, `ReuseaddrErr`, `ReuseportErr`, `NonblockErr`, `BindErr`, `ListenErr`, `AcceptErr`, `ConnectErr`, `ReceiveErr`, `SendErr`, `ResolveErr`, and `LocalErr`. `nonblock(socket: Socket, enabled: bool): Error` is the separate reversible mode operation; it has its own static error domain, performs no hidden socket-state tracking, and is not folded into initial socket creation. A creation-mode convenience remains additive. Nonblocking connection-in-progress behavior is deferred to the nonblocking-I/O carving.
    - `listen(socket: Socket, backlog: usize): Error` performs only the listen transition. The backlog is a requested pending-connection count; the OS may cap it, and a value outside the platform call's representable range fails rather than truncating. It neither performs other setup nor closes/replaces the socket on failure.
    - TCP byte I/O is `receive(socket: Socket, buffer: []u8): (int, Error)` and `send(socket: Socket, data: []u8): (int, Error)`. Each performs one receive or send operation, returns partial counts as-is, and never retries or allocates. Receive returns `0` with null error for orderly peer shutdown. Send accepts `string` and `[]char` values by shared identity, while its `[]u8` spelling states transport-byte intent. Send privately uses the platform's per-operation no-signal flag, so a closed peer produces the ordinary send error instead of terminating the process with `SIGPIPE`.
    - `accept(listener: Socket): (Socket, Addr4, Error)` performs exactly one accept attempt and consumes at most one pending connection. On success the listener remains open and listening, while the returned socket retains the properties produced by the platform accept operation; Ace performs no subsequent mode or option configuration. Portable event-loop code therefore configures the accepted socket explicitly rather than assuming inherited nonblocking state. On failure it returns `Socket(-1)`, canonical-zero `Addr4`, and the operation-specific error without retrying; interruption, an aborted pending connection, would-block, and resource failures remain caller-visible through `sys.errno()`.
    - Implementation organization: the multi-file std module lives in `std/net/`; `mod.ace` is its sole external surface and selects `./os/darwin-arm64.ace` or `./os/linux-x64.ace` with `@when`, while each target file owns that OS's socket externs, constants, ABI structs, conversions, and the one implementation of each operation. Target-layer declarations used by the facade are module-internal and cannot be imported from outside `net`. The supported targets are darwin-arm64 and linux-x64 (glibc); each target file carries the complete surface. Error domains keep one variant set with each target's errno numbers; `ResolveErr` uses the resolver's own status codes, which glibc makes negative (`EAI_*`), beside the local `invalid` (`EINVAL`). Domain-specific bindings do not move into `sys`. Windows remains a separate future checkpoint because its socket handles and completion model do not naturally match the `Fd` alias.
    - `connect(socket: Socket, address: Addr4): Error` performs exactly one connection attempt. On a blocking socket it returns null once connected or the operation-specific error on failure; it does not retry, close, replace, or configure the socket. Nonblocking outbound completion/error querying, peer-address queries, TCP half-close, and additional TCP options are additive operations deferred until required.
    - `local(socket: Socket): (Addr4, Error)` queries the socket's current local IPv4 endpoint through one OS operation. It changes no socket state and returns canonical-zero `Addr4` with `LocalErr` on failure. After binding port zero, it exposes the OS-selected host-order port without port guessing or process-ID coupling. A socket not yet explicitly bound may report the OS-defined wildcard endpoint; peer queries remain additive.
    - Blocking IPv4 name resolution is `resolve4(host: string, port: u16, addresses: []Addr4): (usize, Error)`. It performs one synchronous platform-resolver request, writes addresses in resolver order into caller-owned storage until that storage is full, applies the supplied host-order port to every written address, and returns the number written. Unwritten elements are unchanged. An empty output slice, a hostname longer than the DNS maximum of 253 bytes, an embedded NUL, resolver failure, or a successful lookup with no IPv4 TCP address returns zero and `ResolveErr`; success writes at least one address and returns null error. The initial result does not report whether additional addresses were truncated and exposes no platform-specific resolver code; unlike a socket-operation failure, `sys.errno()` does not describe a resolver failure. On Darwin and Linux the private implementation uses `getaddrinfo`/`freeaddrinfo`: the platform temporarily allocates its result list, `net` copies from it and frees it before returning, and no allocation or resolver-owned pointer escapes into Ace. This paired temporary platform allocation is an explicitly approved narrow resolver-boundary exception to the ordinary no-hidden-allocation rule. A future native DNS client may remove the exception while preserving the public operation; richer diagnostics, truncation discovery, IPv6, asynchronous resolution, caching, search-policy control, and caller-selected socket types remain additive.

Descriptor polling (implemented) — readiness is the separate multi-file std module rooted at `std/poll/mod.ace`, not part of `net`; it accepts general `sys.Fd` values so sockets, pipes, TTYs, and other supported descriptors share one facility. Its explicit `./os/darwin-arm64.ace` implements kqueue privately, and `./os/linux-x64.ace` implements level-triggered epoll. `Queue: distinct sys.Fd` is created by `queue(): (Queue, Error)` with `Queue(-1)` on failure and closed explicitly through `sys.close(sys.Fd(q))`; the queue owns and closes no watched descriptor. `watch(q, fd, readable: bool, writable: bool): Error` registers an fd or replaces its complete readable/writable interest, while `unwatch(q, fd): Error` removes that relationship without closing the fd. On Darwin, `watch(q, fd, readable, writable, context: *u8): Error` also stores `context`, which `poll` never dereferences; the caller keeps it valid while the fd is watched. Both interests false is `WatchErr` with `EINVAL`; unwatching an unwatched fd is `UnwatchErr` with `ENOENT`. A failed multi-filter kqueue update may leave partial state, so callers must watch or unwatch again before relying on that registration; an epoll update (add, or modify when already watched) is atomic. Linux adds `WatchErr` variants `unsupported` (`EPERM`, for example a regular file) and `watch_limit` (`ENOSPC`). The paired names follow the general convention that an establishing/reversing relationship uses an accurate lexical pair; semantic accuracy outranks superficial symmetry.
    - Readiness events are level-triggered `Event: struct { fd: sys.Fd, context: *u8 = null, readable: bool, writable: bool, error: bool, hangup: bool }`. An event from a watch with non-null context reports that context and `fd` -1 on every target, because epoll's data word holds only one value. At most one returned event represents each fd; OS notifications for that fd are combined. Readable includes an EOF-producing read where applicable, writable promises only that a write-like operation may progress, hangup may coexist with remaining readable data, and error carries no errno value; all bools are independent. Error/hangup need no registered interest. On Linux, hangup is `EPOLLHUP` or `EPOLLRDHUP` and also sets readable when the fd has read interest, which the epoll data word carries beside the fd, as a kqueue read filter's EOF does. The implementation uses bounded fixed stack collection (currently 64 raw events), may return fewer descriptors than the caller's capacity, allocates nothing, and keeps no registration side table.
    - `wait(q, events: []Event, timeout_ns: u64): (usize, Error)` performs one blocking OS collection, fully initializes only `events[0..count]`, leaves the suffix unchanged, and returns zero with null error for timeout/no readiness. An empty slice fails before the OS with `WaitErr` and `EINVAL`. `0` polls; `FOREVER: const u64` (u64 max) blocks without a timeout; other values are finite nanoseconds passed as exact seconds/nanoseconds to kqueue; Linux `epoll_wait` takes whole milliseconds, so the duration rounds up (never ending early) and caps at the i32 maximum (about 24.8 days). `EINTR` is caller-visible with no private restart. `QueueErr`, `WatchErr`, `UnwatchErr`, and `WaitErr` are distinct static operation domains with runtime errno queried immediately through `sys.errno()`. Signals, process/vnode/user filters, timers, edge/one-shot triggering, directional half-close, completion I/O, and concurrent mutation guarantees remain additive.
    - The implemented nonblocking server proof composes these primitives into one single-threaded multi-client event loop. Client slots, receive assembly, pending broadcasts, per-recipient send offsets, and returned events all live in fixed caller-owned storage. Read and write interest is replaced as that explicit state changes; disconnect handling unwatches and closes the descriptor before making its slot reusable. Partial receive/send progress belongs to the application, and one completed message is broadcast only to the clients connected at that point. The proof adds no queue-owned client state, allocation, retry policy, worker thread, atomic operation, or higher-level networking convenience.

15. Blocking TCP composition (implemented) — `tcp` is a pure-Ace IPv4 module above the one-operation `net` layer, nested under it and rooted at `std/net/tcp/mod.ace` (imported as `net/tcp`). It declares `Listener: struct { socket: net.Socket, active: bool }` and the `Conn` wrapper whose complete Stage 2 shape is stated below; both are ordinary copyable manual-handle values with no ownership tracking, destructor, or hidden cleanup. Every field declares its canonical-zero default, so `Listener {}` and `Conn {}` spell the empty handle. `active` is true exactly for a handle returned by a successful constructor or accept; canonical zero is therefore the empty handle even though descriptor zero is valid, matching `sys.Dir`. `listen(address: net.Addr4, backlog: usize): (Listener, Error)` composes `net.socket(tcp)`, `net.reuseaddr(true)`, `net.bind`, then `net.listen`, never enables `reuseport`, and on any setup failure closes the created socket while returning canonical-zero `Listener` plus the original setup error even if cleanup fails. `connect(address): (Conn, Error)` similarly composes creation and blocking connect, closes on connect failure, and returns canonical-zero `Conn` plus the original error. `local(listener)` preserves `net.local`; `accept(listener)` performs one blocking `net.accept` and returns a `Conn`, peer `net.Addr4`, and the original accept error on failure.
    - `watch(q: poll.Queue, connection): Error` registers the connection's socket with `poll.watch` under exactly its current interest; it is the only way to poll a connection, whose socket stays private.
    - `receive(connection, buffer: []u8): (int, Error)` is exactly one `net.receive` on the connection's socket, with its count, EOF, and error unchanged; the socket itself stays private.
    - `receive_all(connection, buffer: []u8): (usize, Error)` repeatedly calls `net.receive` over the unfilled suffix until the complete destination is filled. Success returns its full length and null; orderly EOF first returns retained progress and `ReceiveAllErr(0)`; any other failure returns retained progress and the unchanged `net.ReceiveErr`. `send_all(connection, data: []u8): (usize, Error)` similarly calls `net.send` over the unsent suffix; success returns the full length and null, send failure retains progress and the unchanged `net.SendErr`, and a successful zero-progress send returns retained progress with `SendAllErr(0)`. Both retry only an underlying operation error whose code is `sys.EINTR`; they are blocking-only, allocate nothing, and add no one-attempt `send` or `receive` aliases because callers use `net` directly for those semantics. Empty buffers succeed with zero progress.
    - `close(&listener)` and `close(&connection)` on an inactive handle perform no syscall, leave the value unchanged, and return null, so a deferred close may precede the constructor's error check exactly as `mem.release` may on a null slice. On an active handle each attempts `sys.close`, then replaces the caller's complete wrapper with canonical zero even when close fails, returning the `sys.CloseErr` unchanged. Copies are not found or deactivated; closing a stale active copy has the ordinary manual-handle hazards. The public high-level domains are exactly `ReceiveAllErr` and `SendAllErr`; constructor, accept, query, I/O, and close failures otherwise preserve their lower-layer domains and codes. `sys.EINTR` is the public target-defined `i32` name required for this explicit retry policy.
    - Stage 2 nonblocking connection progress (implemented) extends `Conn` to `struct { socket: net.Socket, interest: Interest, send_offset: usize, active: bool }`. `Interest: enum { none, read, write, both }` has canonical-zero `none`; it states the current level-triggered registration requested from `poll`. The fields remain visible machine state, but `tcp` operations maintain the latter two. Buffers are never retained: callers supply them on every progress call and own their storage, capacity, logical receive occupancy, and peer identity. `Event: union { none, data: usize, sent: usize, connected, disconnected, failed: Error }` returns exactly one explicit state change per call. `data(n)` and `sent(n)` are bytes newly transferred by that call; `disconnected` means receive EOF or exactly `ECONNRESET`; `failed(error)` carries every other unrecoverable lower-layer error unchanged.
    - `connect_nonblock(address: net.Addr4): (Conn, Error)` composes socket creation, `net.nonblock(true)`, and one or more interrupted `net.connect` attempts. Immediate success returns read interest; `ConnectErr(EINPROGRESS)` is successful pending construction with write interest. Other failure closes the socket, returns canonical-zero `Conn`, and preserves the original error even if cleanup fails. `progress_connect(&connection): Event` is called after pending-connect write readiness and is the only TCP operation using `net.pending_error`: no stored error changes interest to read and returns `connected`; either a stored `ConnectErr` or query `PendingErrorErr` changes interest to none and returns `failed(error)`.
    - `progress_receive(&connection, destination: []u8): Event` and `progress_send(&connection, source: []u8): Event` each retry `EINTR` but otherwise make one nonblocking socket attempt. `EAGAIN`/`EWOULDBLOCK` returns `none` and enables the corresponding interest. Positive receive returns `data(n)` and suspends read interest, providing explicit backpressure until the caller attempts receive again; the caller appends by passing its writable free suffix. Receive zero or either operation's `ECONNRESET` changes interest to none and returns `disconnected`; every other error changes interest to none and returns `failed(error)`. A positive send returns `sent(n)`; partial completion enables write interest, while complete-source completion resets `send_offset` to zero and removes write interest. While `send_offset` is nonzero, every call must pass the same complete source descriptor and backing bytes unchanged; this is a programmer precondition because the connection deliberately retains neither pointer nor length. `send_all` must not be mixed into an unfinished progress send: its precondition is `send_offset == 0`. An empty receive destination performs no syscall, returns `none`, and suspends read interest. An empty send source performs no syscall, resets the offset, removes write interest, and returns `sent(0)`. A successful zero-progress nonempty send returns `none` and enables write interest. `interest(connection)` returns the current value without mutation. Blocking construction and acceptance initialize read interest; progress operations take a connection from `connect_nonblock` or `accept_nonblock`, since the descriptor of one from blocking `accept` is private (Modules #3). Stage 1 blocking operations otherwise retain their rules. Closing zeros every added field even on failure.
    - The low-level prerequisite `net.pending_error(socket): Error` performs one `getsockopt(SO_ERROR)` query. No stored error returns null, a nonzero stored connection result returns `ConnectErr(code)`, and failure of the query itself returns `PendingErrorErr(errno)`. `sys.EINPROGRESS` and `sys.ECONNRESET` are public target-defined codes used by this policy. The reactor remains pure Ace over `net`/`poll`/`sys`, allocates nothing, owns no buffer, and delivers no callback.
