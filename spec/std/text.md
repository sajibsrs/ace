## Stdlib: character and string utilities

Stdlib #16; the chapter's shared rules are in `spec/std/README.md`.

16. Character and string utilities:
    - `char` is a predeclared transparent alias of `u8`, with shared identity, representation, conversions, and overload behavior; `sizeof(char) == 1`. It names one byte used as character data, not a decoded Unicode character. Character literals remain untyped constants holding exactly one byte and retain the existing escapes (`\n`, `\t`, `\r`, `\0`, `\\`, `\"`, `\'`, and `\xNN`); a direct multibyte source character in a character literal remains invalid. Strings remain read-only UTF-8 byte sequences with byte length, indexing, slicing, and iteration. Unicode code points are plain `u32` values; UTF-8 encoding and decoding happen only through explicit `utf8` calls, and no decoding, normalization, or grapheme processing is implicit.
    - `str` is an ordinary free-function module. Strings gain no methods, and no primitive-method or generic-method facility is introduced. Exact overload selection treats `char` and `u8` as the same type, so a `char` overload is also the byte overload.
    - `ascii` is an ordinary allocation-free module over ASCII bytes and byte strings. `ascii.control(byte: u8): bool` recognizes exactly bytes `0x00..0x1F` and `0x7F`. `ascii.lower(byte: u8): u8` maps `A..Z` to `a..z` and leaves every other byte unchanged. `ascii.equal(a: string, b: string, sensitive: bool): bool` compares exact bytes when `sensitive` is true and compares after that ASCII-only lowercase mapping when false; unequal lengths fail, and bytes outside ASCII letters remain unchanged. It performs no Unicode decoding, normalization, locale processing, or allocation.
    - `utf8` is an ordinary allocation-free module over UTF-8 byte strings, validating strictly per RFC 3629: overlong forms, surrogates `0xD800..0xDFFF`, values above `0x10FFFF`, truncated sequences, and unexpected continuation bytes are invalid. `utf8.decode(text: string, at: usize): (u32, usize, bool)` decodes the one sequence starting at byte `at`; success returns the code point, its byte width (1–4), and `true`. Invalid input returns `(0, 1, false)`: the width stays 1 so every call at `at < text.len` advances a decode loop, a deliberate exception to the canonical-zero failure rule. `at >= text.len` returns `(0, 0, false)`. `utf8.encode(value: u32, destination: []char): (usize, bool)` writes the complete encoding and returns its width and `true`; an invalid code point or insufficient capacity returns `(0, false)` without writing, and the unused destination suffix is unchanged. `utf8.width(value: u32): usize` returns the encoded width, or 0 for an invalid code point. `utf8.valid(text: string): bool` reports whether the complete text is well-formed; empty text is valid. No operation normalizes, folds case, or applies locale rules.
    - Search is allocation-free and byte-exact. `str.find(text: string, needle: string): (usize, bool)` and its `needle: char` overload return the first byte index and `true`, or canonical-zero `usize` and `false`; an empty string needle is found at zero. `str.has(text, needle)` has `string` and `char` overloads and tests occurrence anywhere; an empty string needle is present. The corresponding three-argument overloads `str.has(text, part, suffix: bool)` test one boundary: `false` selects the prefix and `true` the suffix. An empty string part matches either boundary.
    - `str.compare(a: string, b: string): int` compares unsigned bytes lexicographically and returns exactly `-1`, `0`, or `1`; after an equal prefix, the shorter string sorts first. It allocates nothing and performs no Unicode decoding or normalization.
    - `str.copy(text: string, noalias destination: []char): bool` copies the complete text into `destination[0..text.len]`. A shorter destination returns `false` and is unchanged; otherwise the copy succeeds, returns `true`, and leaves the destination suffix unchanged. Empty text succeeds without writing. The source and written destination range must not overlap; debug builds diagnose a false promise and release assumes it. This is a capacity-oriented convenience, unlike `mem.copy`, whose two complete ranges must have equal lengths.
    - `str.cstring(text: string, noalias destination: []char): bool` copies the text followed by a NUL byte, for C functions that read text up to its NUL. It fails when `text.len + 1 > destination.len` or the text holds a NUL byte, leaving the destination's contents unspecified; success leaves the suffix after the NUL unchanged. It allocates nothing and is for code above `sys` (Standard Library #22).
    - `str.concat(parts: []string, destination: []char): (usize, bool)` concatenates every part in order into caller storage. Success returns the complete byte count and true while leaving the unused destination suffix unchanged. If the complete result exceeds destination capacity, it returns `(0, false)` and the destination's contents are unspecified; the parts are copied in one pass that stops at the first part that does not fit. Empty parts and an empty parts slice are valid. Source bytes must not overlap the written destination range. The operation allocates nothing and performs no decoding or normalization.
    - `str.split(text: string, separator: string, parts: []string): (usize, bool)` and its `separator: char` overload split left-to-right on non-overlapping exact byte matches. Separators are omitted; leading, trailing, and adjacent separators produce empty parts, and empty input produces one empty part. Each written part is a zero-copy view into `text`; unwritten slots are unchanged. The result is the number written and whether the complete result fit. An empty string separator returns `(0, false)` without writing. The operation allocates nothing and performs no decoding or normalization.
    - Exact boundary removal is overloaded as `str.trim(text: string, part: string, suffix: bool): (string, bool)` and with `part: char`; `false` removes at most one matching prefix and `true` at most one matching suffix. A match returns the remaining zero-copy view and `true`; absence returns the original view and `false`; an empty string part succeeds without changing the view. `str.trim(text: string): string` instead removes all leading and trailing ASCII whitespace bytes — exactly `0x09..0x0D` and `0x20` — and returns a zero-copy view. It performs no Unicode whitespace processing.
    - Parsing is the explicitly instantiated generic overload set `str.parse[T](text: string): (T, bool)` and `str.parse[T](text: string, radix: u8): (T, bool)`. The default form admits exactly `int`, `uint`, `usize`, `f32`, and `f64`; the radix form admits exactly the three integer types and radices 2 through 36. Integer digits above nine are ASCII letters, case-insensitive. An explicit radix accepts digits only, with no `0x` or `0b` prefix. Parsing consumes the complete nonempty string, accepts no surrounding whitespace or leading `+`, permits leading `-` only for `int` and signed floats, and accepts leading zeroes. Decimal floats accept ordinary decimal/scientific forms plus the exact non-finite spellings produced by `fmt` (`nan`, `inf`, `-inf`). Finite decimals round directly to the requested IEEE width using nearest with exact ties to even; conversion does not pass through another float width. Parsing assumes the default round-to-nearest floating-point environment. Invalid text, an unsupported runtime radix, or overflow returns canonical-zero `T` and `false`; finite float underflow rounded to signed zero succeeds. Unsupported `T` is a compile-time error. Parsing allocates nothing, performs no locale-dependent interpretation, and uses no platform decimal parser.
    - Value-to-text conversion is the ordinary overload set `str.format(destination: []char, value): (usize, bool)` for exact value types `int`, `uint`, `usize`, `f32`, and `f64`, plus radix-taking overloads for the three integer types. A runtime radix outside 2 through 36 writes nothing and returns `(0, false)`; insufficient capacity returns `(0, false)` with the destination's contents unspecified. Success returns the byte count and `true`, leaving the unused destination suffix unchanged. Integer radix digits are lowercase ASCII and carry no base prefix; only `int` may emit `-`. The no-radix float representations are exactly those of the corresponding `fmt.print` overloads. The operation allocates nothing.
    - Formatted text into caller storage is the `str.format` overload `str.format(destination: []char, format: string, ...): (usize, bool)`, selected when the second argument is a `string`. Its format and value arguments follow `fmt.printf` exactly (Standard Library #12): a compile-time-static format, the same conversions, exact argument types, precision rule, width, and diagnostics, and every argument evaluated once in source order before any byte is written; no runtime parser, allocation, variadic call, or C formatting. The compiler lowers it exactly as `fmt.printf`, through the same sink and piece writers, with the destination as the storage and a drain that refuses, so the first piece that does not fit fails the call. Success returns the byte count and `true`, the text being `destination[..n]`, with no NUL appended — C-bound text writes `\0` in the format — and the unused suffix unchanged. Insufficient capacity returns `(0, false)` with the destination's contents unspecified. Like `fmt.printf` it is direct-call-only.
