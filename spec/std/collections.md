## Stdlib: `array`, `map`, and `file`

Stdlib #18–20; the chapter's shared rules are in `spec/std/README.md`.

18. Growable array (implemented) — `array` is a single-file pure-Ace module over `mem.grow`. `Array[T]: struct { items: mut []T = null, len: usize = 0 }` holds `len` live elements at the front of `items`, whose length is the capacity; the canonical zero value and `Array[T]{}` are valid empty arrays, and a zero-capacity array holds no storage. `Array[T].new(capacity: usize): (Array[T], Error)` is an associated function and `wipe()` an ordinary mutating method. The methods are `push(value): Error`, `reserve(count): Error`, `pop(): (T, Error)`, `get(index): T`, `set(index, value)`, `view(): []T`, `clear()`, `truncate(count)`, and `wipe()`; mutating methods are called with `mut`. `view` is overloaded on the receiver: `view(mut self): mut []T` writes live elements in place (`mut xs.view()`). Allocation failure returns `ArrayErr.allocation` and leaves the array unchanged; `pop` on an empty array returns `blank(T)` and `ArrayErr.empty`. `get` and `set` are checked against `len`, not capacity, through a slice of the live prefix, adding no new mechanism. `truncate(count)` drops every live element from `count` onward and keeps storage, following the ordinary sequence bounds contract (debug builds diagnose `count` past the current length; release assumes it) rather than adding a new error case. Element type arguments are bare named types (Generics #12).
19. Runtime hash map (implemented) — `map` is a single-file pure-Ace module over `mem`. `Map[K, V]: struct { slots: mut []Slot[K, V] = null, len: usize = 0 }` holds `len` live entries in `slots`, whose length is the capacity, a power of two or zero; the canonical zero value and `Map[K, V]{}` are valid empty maps holding no storage. `Slot[K, V]` is `{ key: K, value: V, used: bool }`, and fresh slot arrays come from `mem.zalloc`, so every slot starts unused. `Map[K, V].new(capacity: usize): (Map[K, V], Error)` is an associated function and `wipe()` an ordinary mutating method. The methods are `get(key): (V, bool)`, `has(key): bool`, `set(key, value): Error`, `unset(key): bool`, `reserve(count): Error`, `clear()`, and `wipe()`; mutating methods are called with `mut`. `set` inserts or overwrites; `unset` reports whether the key was present; `get` on a missing key returns `blank(V)` and false. `MapErr.allocation` is the only error; on failure the map is unchanged. Storage is open addressing with linear probing, growing by rehash into a fresh allocation whenever an insertion would exceed 3/4 load; the load factor is fixed and not a knob. `unset` uses backward-shift deletion, so no tombstones exist. The key contract is two private `specialized` generics, `hash[K](key: K): u64` and `same[K](a: K, b: K): bool`, specialized exactly for `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`, `usize`, `bool`, and `string` (Generics #9–#14), which also covers `int`, `uint`, and `char` as transparent aliases; any other key type is a compile-time error at the instantiation, and enums, distinct types, and composite keys are additive once specializations outside the generic's module exist. `string` keys compare through `mem.equal`, never `==` (Values & Passing #11). Integer hashes are a 64-bit finalizer built on `bits.wrmul`, and a string hash is FNV-1a 64 followed by the same finalizer. Iteration order and iteration itself are absent from v1, as are value-address accessors, since growth would invalidate them; `get` and `set` copy.
20. Whole-file I/O (implemented) — `file` is a single-file pure-Ace module composing `sys` descriptor calls with `mem`. `read(path: string): (mut []u8, Error)` returns the file in one `mem.alloc` allocation the caller releases with `mem.release`, null on failure; an empty file is null with no error. It opens, sizes the buffer from `stat`, reads until full retrying `EINTR`, and passes `sys` errors through; `FileErr` adds `allocation` and `truncated` (the file shrank below its `stat` size). `write(path: string, data: []u8): Error` truncates or creates the file with mode `0o666` less the umask, as C's `fopen` does, writes all of `data` retrying `EINTR`, and reports a close failure.
